# Architecture decision records

An ADR records one consequential decision: the context that forced it, what
was decided, and what it costs. They are the reason the code is shaped the
way it is — when a rule in [`AGENTS.md`](../../AGENTS.md) or a gate in CI
looks arbitrary, the ADR it cites explains it.

## Reading them

- **Start with the foundations.** [0017](0017-host-client-product-topology.md)
  (host/client topology), [0005](0005-authority-handle-connectionref.md)
  (ConnectionRef, never `getSecret()`), [0090](0090-static-frontend-complete-without-backend.md)
  (the static front end needs no backend) and [0133](0133-shared-app-core.md)
  (one shared client core) shape nearly everything else.
- **Status is the ADR's own.** `Accepted (partly superseded)` means a later
  ADR replaced some sections; the ADR names which.
- **Numbers are not unique.** Parallel work landed a handful of ADRs under the
  same number (0038, 0052, 0054, 0065, 0125, 0130). They are distinct
  decisions and are cited by file name; they are not renumbered because
  hundreds of references point at them.

## Writing one

1. Copy the shape of a recent ADR: title, `Status:`, `Date:`, context,
   decision, consequences.
2. Take the next free number after the highest one below.
3. Run `pnpm docs:index` to add it to this table (`pnpm quality` fails
   until you do).
