# Layout map

Detailed path-by-path layout moved from `AGENTS.md` §4. For a narrative tour see `docs/getting-started/repository-tour.md`; per-directory `README.md` files (`crates/`, `packages/`, `apps/`) are the maintained summaries. Repository-footprint rules are canonical in [repository footprint](../contributing/repository-footprint.md).

## 4. Layout map

Top level: `apps/` (deployables), `crates/` (Rust libraries), `packages/`
(TypeScript libraries and services), `examples/` (runnable integrations on the
public SDKs and shared contract packages, never an app's source), `marketplace/` (vault item-type definitions: `item-types/builtin/` is
embedded by both planes, `item-types/optional/` is indexed by
`.opensesame/marketplace.json`), `spec/` (WIT, Host OpenAPI, OpenFGA model,
connector manifests, and the shared config, conformance vectors, plugin
catalog, log-scrub rules, secret-file and agent-hooks contracts), `tests/`
(cross-cutting suites and shared fixtures),
`tools/` (lint plugins, quality ledgers in `tools/quality/`, mutation configs,
scanner rules, the mock IdP), `scripts/` (what `pnpm` tasks run, one folder
per purpose: `quality/`, `audit/`, `fuzz/`, `test/`, `mtls/`, `release/`,
`dev/`, `wallet/`, `security/`, shared logic in `lib/`), `ops/`
(compose, GitHub governance, ingress, NATS, routines), `skills/`, `patches/`
(pnpm patches for third-party dependencies), `docs/`. Each has a `README.md`
(`patches/` has none); `docs/getting-started/repository-tour.md` says where things go.
Do not add new top-level directories or loose root files — find the group.

### Repository footprint

Follow `docs/contributing/repository-footprint.md` for every task and agent.
Persist source, required fixtures, approved current evidence and concise maintained
findings. Keep scanner runs, raw reviews, assignments, transcripts and generated
working output in ignored `work/` or private temporary storage; summarize results
on the PR. Never append per-run artifact directories to the default branch.

Install third-party skills once under `.agents/skills/`, preserve intentional
agent-specific variants, and run `node scripts/dev/sync-agent-skills.mjs` to
restore shared links. Do not install full copied trees for each harness.
Use the existing dependency, Cargo and browser caches; install only when needed.
Session startup must never generate migrations, baselines or tracked reports.
Clean only task-owned scratch/build output when the task finishes; preserve active
sessions and shared caches. Run `node scripts/quality/repository-size-gate.mjs`
before staging, and review any limit change as a policy change.
