## Mission

You are the orchestrator. Implement OpenSesame’s **Doppler-capability parity**
(projects-first secrets scope, multi-target sync, change logging, rotation,
shared project/env secrets, offline encrypted cache) and **NATS foundations**
(JetStream TaskBus, Host auth callout, mixed-mode multi-IdP admission, E2EE
payloads with xkeys) in one run by delegating the **eight work packages**
below to **parallel** subagents.

The packages are deliberately independent — **no ordering, no phases, no
timelines**: each package owns a disjoint set of files, carries its full
spec, and self-verifies. Spawn **all eight at once**, merge their results,
run the final acceptance checks, and stop (do not push unless explicitly
asked later).

### Product stance (locked)

OpenSesame does **not** become a Doppler clone. It implements **capability
parity** under existing authority / E2EE rules. The catalog provider id
`doppler` (Fnox parity) is a **connector to Doppler SaaS** — it is not this
feature set. Do not conflate them.

| Doppler / NATS ask | OpenSesame mapping |
|--------------------|--------------------|
| Sync to Vercel / Railway / etc. | Host **sync targets**: ConnectionRef → authorize → invoke fan-out; agents never receive raw secrets |
| Projects-first UX | First-class **Host Project** as secrets/env scope; default **personal project** binds initial sealed-store tomb + Pages vault folder |
| Automatic change logging | Durable **secret/config changelog** (identity audit chain + Host receipts + broker events); git commits remain sealed-store local history |
| Automated rotation | TaskBus jobs + broker credential versioning + sealed-store `pass update`-style rotate; schedules via JetStream |
| Shared project/env secrets | Project-scoped sealed entries + connection `shareability` / bindings (ADR 0032 / 0035) — not server-readable vault plaintext |
| Offline encrypted cache | Strengthen OPFS vault + sealed-store + client-core ciphertext blobs; encrypted snapshot export |
| NATS messaging / streaming | Real **JetStream adapter** behind `crates/task-bus` (today InMemory-only) |
| NATS auth callout | **Host** callout (authz + ConnectionRef / OpenFGA); Identity only for principal mapping / token validation |
| Mixed-mode authn / authz | Multiple upstream IdPs via `PrincipalMappingStore`; **no email auto-link** |
| E2EE with xkeys | age / X25519 (sealed-store lineage) + human-vault AEAD for payloads — **never** the broker deployment seal key |

## Hard rules (every subagent inherits these verbatim)

1. **Zero GitHub Actions.** Do not create `.github/` or any workflow file.
2. **No secrets in git.** Use `.env.schema` / env-spec annotations (`@type`,
   `@required`, `@sensitive`, `@public`). Never commit live credentials,
   NATS operator seeds, or xkey private keys.
3. **No sudo** and no privilege-elevation prompts.
4. **Dual plane stays separate (ADR 0017 / 0007):** Host API `:8787` vs
   Identity API `:8788`. Do not merge into a BFF. NATS auth callout lives on
   **Host**, not Identity.
5. **Agent non-disclosure (ADR 0005 / 0032 / 0006):** Never add agent-facing
   `getToken`, `getSecret()`, `show` for agents, or SecretRef as the default
   agent API. Sync fan-out and rotation must use ConnectionRef → authorize →
   invoke → receipt. `doppler run`-style env materialize is **craft bar /
   operator L3 only** — not the agent contract.
6. **Vault ≠ authority credentials (ADR 0032):** Human E2EE vault /
   sealed-store ciphertext stays server-blind. PaaS sync uses
   **authority-plane** sealed connection credentials decryptable by Host for
   egress only.
7. **No Vercel Marketplace / Clerk as core IdP (ADR 0004).**
8. **Do not vendor** Doppler, Infisical, Bitwarden, HashiCorp Vault, or any
   commercial secrets platform as a runtime dependency. Study docs only.
9. **No AGPL incorporation.** Do not copy incompatible source.
10. **`@opensesame/os-domain` must not import** Better Auth, oidc-provider,
    Hono, Drizzle, or React.
11. **File ownership is exclusive.** A subagent may read anything but may only
    create/edit paths listed under its **OWNS**. Shared lockfiles
    (`Cargo.lock`, `pnpm-lock.yaml`) are regenerated by the orchestrator at
    merge — do not hand-merge.
12. **Formatting:** Biome 1.9.4 (2-space) for TS; `rustfmt` / existing Cargo
    style for Rust. Conventional commits if the orchestrator commits
    (`feat(projects): …`, `feat(task-bus): …`, `docs(adr): …`).
13. **Do not edit** `docs/implementation/one-shot-doppler-nats-prompt.md`
    itself (this file) except to fix factual path errors discovered while
    implementing — prefer leaving it alone.
14. **Postgres outbox remains authoritative for Identity events (ADR 0010).**
    JetStream is a drain / Host bus — not a second source of truth. Do not
    dual-write Identity mutations only to NATS.
15. **Fake E2EE is forbidden:** sealing NATS payloads with the Host
    `OPENSESAME_CONNECTION_KEY` / deployment seal key is **not** xkey E2EE.

## Adversarial critique + corrected reading (binding)

Subagents must treat the following as **ground truth**. Refuse the listed
mistakes even if a Doppler/NATS tutorial suggests them.

### What the Doppler/NATS ask gets right

- Projects / configs / environments are a better **operator mental model**
  than “vault dump” for shared app secrets.
- Fan-out sync to PaaS/CI is real operator pain; OpenSesame should own the
  **authority-mediated** path.
- Change history + rotation are table stakes for team secrets.
- Offline encrypted cache matches OpenSesame’s client-plane strength.
- NATS JetStream is already the greenfield bus choice (ADR 0002); auth
  callout + xkeys match a zero-trust mesh story.

### What naive implementations get wrong for *this* repo

1. **Env dump ≠ agent API.** Cloning `doppler run` as the agent contract
   violates ADR 0005 / 0006. Agents use ConnectionRef invoke. Operator
   materialize (L3) stays gated and audited.
2. **Vault ≠ sync-target credentials.** Pushing Pages vault plaintext to
   Vercel via a server that can read VRKs breaks E2EE. Sync uses Host
   connection credentials + project-scoped **authority** secrets (or
   ciphertext envelopes the target decrypts with its own key).
3. **Plane confusion.** Putting NATS auth callout on Identity (`:8788`) as a
   BFF, or letting callout decrypt vault material, breaks ADR 0017 / 0032.
4. **Multi-IdP join on email.** Forbidden. Use `PrincipalMappingStore` /
   pairwise subjects. See
   `docs/security/audit-2026-08-08-identity-link-assurance.md`.
5. **Dual-write split-brain.** Identity Postgres outbox is authoritative
   (ADR 0010). JetStream consumes outbox / Host publishers; it does not
   become a competing ledger.
6. **Fake E2EE.** Broker deployment-key AEAD on NATS payloads is
   server-readable “encryption at rest on the wire.” Reject it. Use xkeys
   (X25519 / age lineage) + human-vault-style AEAD with client-held keys.
7. **TaskBus adapter without producers.** A JetStream crate that nothing
   publishes to is theater. Sync, rotation, and changelog WPs must emit
   CloudEvents-shaped `BusEvent`s.
8. **Catalog `doppler` provider ≠ this product.** Do not “implement
   Doppler sync” by shelling `doppler` CLI into agent paths. Sync targets
   are OpenSesame Host objects that invoke **catalog connectors**
   (Vercel, Railway, GitHub Actions, etc.).
9. **Provisional principal over-privilege.** Callout and sync ACLs must
   distinguish provisional vs verified assurance; org/project gates need
   completed upstream ceremony.
10. **Pairwise correlation.** Do not publish canonical principal IDs on
    public NATS subjects/headers; prefer pairwise or opaque capability
    tokens scoped to the bus.
