## Mission

You are the orchestrator. Implement OpenSesame’s **credential / authorization
broker** upgrades and **connector-catalog** taxonomy in one run by delegating
the eight work packages below to **parallel** subagents. The packages are
deliberately independent — **no ordering, no phases, no timelines**: each
package owns a disjoint set of files, carries its full spec, and self-verifies.
Spawn **all eight at once**, merge their results, run the final acceptance
checks, and stop (do not push unless explicitly asked later).

This work implements a corrected reading of the connector landscape:

- Distinguish **credential/authorization brokers** from **connector catalogs /
  workflow engines**.
- Keep OpenSesame’s agent API as **ConnectionRef → authorize → invoke →
  receipt** — never agent-facing `getToken` / `getSecret`.
- Implement broker primitives **natively in Host**; treat OpenConnector /
  Activepieces as **descriptor adapter sources**; treat Obot / ContextForge /
  MCP Gateway Registry as **protocol prior art** (study, do not vendor).
- Allow operators to register **custom OAuth** and **custom MCP** connectors.

## Adversarial critique + corrected taxonomy (binding)

Subagents must treat the following as **ground truth**, not the raw “OpenConnector
+ Obot = OSS Vercel Connect” marketing composition.

### Taxonomy (two classes)

| Class | Meaning | Examples |
|-------|---------|----------|
| **Credential / authorization broker** | Workload/user principal → policy → connection object → (internal) credential use; ideally agent never sees upstream token | Vercel Connect, Obot, IBM ContextForge, MCP Gateway Registry, OpenSesame Host broker |
| **Connector catalog / workflow engine** | Provider→action vocabulary, Pieces, syncs, iPaaS workflows | OpenConnector, Activepieces, Nango Functions, n8n, Automatisch, Airbyte |

A project may be strong in one class and weak in the other. **Do not conflate.**

### What the landscape analysis gets right

- The broker vs catalog split is correct and under-documented in OpenSesame.
- OpenConnector is the strongest OSS **execution/catalog** peer (Apache-2.0,
  large Actions surface, credentials behind gateway).
- Obot / ContextForge / MCP Gateway Registry are the right **control-plane**
  research set (token exchange, per-user credentials, MCP governance).
- Nango is functionally mature but **ELv2**, not OSI OSS.
- Nine primitives below are the evaluation scorecard.
- Custom OAuth/MCP for unlisted connectors is mandatory.

### What it gets wrong for *this* repo

1. **Do not adopt OpenConnector + Obot as runtime foundations.** They do not
   integrate as a supported stack. Vendoring them fights ADR 0017 / 0005.
   Implement primitives in Host; use catalogs as **descriptor adapters**; study
   Obot/ContextForge for RFC 8693 / MCP OAuth patterns.
2. **OpenConnector is not a 9/10 replacement for OpenSesame’s control plane.**
   OpenSesame already has catalog + authorize + invoke + receipt. Treat
   OpenConnector as a high-value **adapter/ecosystem peer**.
3. **Vercel Connect `getToken` must not become the agent API.** Implement
   broker-**internal** refresh / RFC 8693-shaped exchange for Host→provider
   egress only. Agents use ConnectionRef invoke.
4. **Activepieces = adapter source**, not broker or workflow runtime adoption.
5. **Automatisch (AGPL) / n8n / Airbyte / Windmill** are rejected broker
   foundations (workflow/data movers). One-line “rejected” note only.
6. **Unauthenticated MCP prevalence** reinforces ADR 0023: auth-bound MCP,
   no secret tools, no inbound-token passthrough as upstream provider creds.
7. **SPIFFE / RFC 8693 must leave “aspirational slug” status** via WP-D code.

### Nine primitives (scorecard columns for WP-A)

1. Workload attestation (OIDC/SPIFFE, not app master keys)
2. Subject delegation (human, workload, service, agent)
3. Connection object ≠ credential
4. RFC 8693 / token exchange where possible (Host-internal)
5. Scope/resource downscoping
6. Credential non-disclosure to agents
7. Environment/project/tenant binding
8. Immediate revocation + auditability
9. Webhook/event provenance / re-attestation

### Locked architecture

```text
Agent / Pages / Workload
        │
        ▼
┌───────────────────────────────┐
│ Host connection broker        │
│  identity admission           │
│  policy (AuthZEN/OpenFGA)     │
│  connection object            │
│  sealed credentials           │
│  internal token exchange      │
│  catalog + custom providers   │
└───────────────┬───────────────┘
                │ invoke (L1/L2)
                ▼
         connector-host → SaaS / MCP upstream
                │
                ▼
             receipts

Capability descriptors (offline adapters, not runtimes):
  OpenConnector-shaped JSON, Activepieces Piece-shaped,
  OpenAPI ops, MCP tool schemas, bundled catalog.json ops
        → ConnectorCapability
        → catalog / invoke ops
```

**Canonical rule:** A **Connection** is an authorization relationship
(provider, tenant, subject, project/environment, capabilities, resources,
policy). Credentials are sealed under the broker. Agents never receive
reusable upstream tokens.

### Spec

#### Data model

Persist org-scoped custom providers:

```text
CustomProvider {
  id: string,                 // "custom:<slug>" or "custom:<uuid>"
  organization_id: string,
  display_name: string,
  auth_kind: "oauth2_authorization_code" | "mcp",
  // oauth2:
  authorize_url?, token_url?, client_id?,
  // client_secret write-only at create/update — sealed like integrations
  scopes?: [{ name, description?, sensitive?, default? }],
  egress?: { scheme, authorities[], path_prefixes[] },
  operations?: string[],      // optional typed ops; default ["proxy.http"] for oauth2
  // mcp:
  mcp_server_url?,
  mcp_transport?: "http" | "sse",
  mcp_auth?: "oauth2" | "none" | "header",
  created_at, updated_at
}

for the caller’s org. Custom entries set `"source": "custom"`.

#### HTTP API (gateway)

```
POST   /api/v1/providers/custom
GET    /api/v1/providers/custom
GET    /api/v1/providers/custom/{id}
PATCH  /api/v1/providers/custom/{id}
DELETE /api/v1/providers/custom/{id}
