# Customer envelope encryption: surface validation

This records the implementation and validation status on 2026-10-05. A shared deployment derives distinct wrapping keys from trusted customer, vault, principal, or record identity. The osev2, osc2, osr2 and local-record formats use fresh data encryption keys for each seal. Vault formats also use wrapped vault data keys, which can persist across body updates. This is logical cryptographic segmentation under a deployment root: possession of that root still grants access to its derived keys. Independent customer root custody requires an external key-management boundary.

Counts below distinguish completed software tests from hardware and deployment validation. Full workspace checks cover every registered app/package test target, rather than only the CLI or PWA. Existing legacy ciphertext remains readable where explicitly supported; database startup sweeps upgrade existing persisted records before serving traffic. Older binaries cannot safely read the new durable schema and formats; follow the rollout and rollback guidance accompanying the migrations.
