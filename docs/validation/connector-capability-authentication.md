# Connector capability and authentication audit

This audit covers all 225 listed provider identities, including aliases. It checks the actual compiled browser contracts, current-origin admission, and the verified-record requirements used by the catalog cards. It does not claim 225 live customer accounts or authenticated provider grants.

## Current source and card states

A source-contract scenario with connector drivers compiled, no saved connections, the measured admission for `https://tyler-r-kendrick.github.io`, and strict opener isolation for Google contains 89 potentially eligible browser identities, 125 outside-browser identities, and 11 blocked identities. These are source capability counts, not measured live deployment glyphs: actual instance policy, egress permission, provider client registration, and runtime admission must still agree before a card offers connection. A permitted header-less deployment adds the actual Google SDK consent route; provider-origin restrictions and successful authorization still apply.

The source includes 17 public OAuth/SDK/device profiles, 48 complete admitted preset API credential verifiers, the explicit GitHub personal-token and S3 SigV4 drivers, and Vault/OpenBao instance OIDC/token drivers. These route counts overlap. Of 71 complete public MCP contracts, 37 have measured current-origin admission denials and 34 remain eligible for actual discovery/authorization. Eligibility is not provider verification.

- **Plus:** a compiled browser route is admitted by this deployment. OIDC/OAuth consent takes precedence over pasted credentials when supported.
- **Ellipsis:** a matching active native record proves verified access, has no unresolved cleanup, and has unexpired credentials. APIs need not invent an account identity; anonymous MCP requires an actually verified current MCP resource. Linear uses its verified workspace binding.
- **Arrow:** an executable saved browser authorization needs resuming, or a genuine native record requires repair/cleanup. A legacy saved URL with no browser driver remains a computer indicator.
- **Computer:** the listed route needs an application/server outside this browser. It is a capability indicator; no invented installer or generic configuration form is opened.
- **Blocked:** the payment policy refuses the integration, or an unsupported wallet has no admitted executable route.

## Completed provider behavior and verification

GitHub personal tokens verify the actual account and repositories; GitHub App configuration that requires confidential server credentials does not impersonate that route. S3 verifies selected bucket access with signed SigV4 requests. Their installed state requires the private provider verification, not a saved URL or configuration flag.

Vault/OpenBao select instance-approved OIDC consent before token entry. The actual callback validates the returned instance token; usable KV reads run against provider authorization. Namespace and KV version/path settings are part of the verified instance contract.

Google uses an approved header-less deployment's reserved consent page. The page scrubs its public fragment, loads the official GIS SDK, and enables a second-click consent button. Returned bearer material is encrypted to the initiating browser runtime and durably journaled before acknowledgement. Verification and activation occur only after authorization returns and cancellation is checked. Cancellation or lock during journaling preserves issued credentials for cleanup without activating the connection. Failed handback attempts actual SDK revocation and reports unresolved cleanup if revocation cannot be confirmed. Strict vault isolation is unchanged; that deployment shows the computer capability glyph.

The origin-scoped MCP admission rules gate configuration, authorization, verification, refresh and every provider operation before HTTP. Driver support remains compiled independently so already-issued credentials can still be cleaned up after admission changes.

## Evidence and limits

The public probe receipts contain 284 TLS-verified metadata/OPTIONS requests and 119 registration/resource-header/SSE followups. No client registration, token exchange, customer account, or authenticated provider data was requested. Missing/wrong CORS and required protocol-header failures are distinguished from transport failures. The 37 measured denials apply only to the audited origin, not universally to other self-hosted deployments. Successful public metadata or preflight never establishes authenticated access.

The MCP SDK test proves that `MCP-Protocol-Version` is sent on post-initialization requests without requiring an optional session identifier. Adobe, Local Falcon and Sanity omit this mandatory header in measured preflights. The transport requirement is documented in the [MCP HTTP specification](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports#protocol-version-header).

The reusable Google browser gate builds the exact callback entry for a separate permitted header-less fixture. It intercepts the official GIS SDK contract, checks second-click activation, fragment scrubbing, encrypted cancellation and retained credentials during lease cancellation. It removes SDK request interception before checking an actual cross-origin OPTIONS/authorized resource fixture, so Chromium enforces CORS. It is an SDK/transport contract proof, not a live Google customer grant. Actual Vault/OpenBao provider-service proofs run separately in the same gate.
