Three ways to wear the connectors

The same five core connectors, up top, always visible. Click any glyph to cycle it — live, needs attention, off — and see how each treatment holds up. Pick one and the rest of the design follows it.

Option A

Glyph row — the phone status bar

OpenSesame

Personal ▾

Quietest, and the most status-bar-true: five glyphs read as one object, and an amber pip is the only thing that ever pulls the eye. Costs discoverability — nothing says which glyph is the git server until you hover, so it leans on tooltips and on people learning the row.

Option B

Glyph plus micro-label

OpenSesame

Nothing to learn — the row names itself, and state is carried twice, in colour and in wash, so it survives a glance. Costs roughly 210px of bar and stops reading as a status bar; on a phone the labels have to drop anyway, so you end up maintaining A as well.

Option C

One summary chip, popover on click

OpenSesame

Cheapest on chrome and the only one that scales past five connectors — the popover has room for the detail line each connector actually wants to show. Costs a click before you can see anything, which is the wrong trade for the one job this bar exists to do: tell you at a glance that the host is down.

All three read what the rail status already reads: usePlaneStatus() for host and identity, the daemon probe for this machine, and the capability bindings for keys and git history. States map straight across — live and pending are green, down and loopback amber, unset ghosted with no pip.
